# M1.5 "In a Box" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship EarlyWeb as an installable Tauri v2 desktop app that stores files as real files under `~/EarlyWeb/`, serves its bundled apps over `ewapp://` with per-app CSP, proves apps cannot reach Tauri IPC, and auto-updates from GitHub Releases.

**Architecture:**

- The existing Preact shell becomes the Tauri webview's frontend, unchanged except for one new seam. `packages/shell/src/platform.ts` picks the backends at boot: `web` (IndexedDB plus the Node app server, as in M1) or `tauri` (Rust commands plus `ewapp://`).
- All security-relevant Rust logic lives in a plain library crate, `earlyweb-core`, with no Tauri dependency. It holds the virtual-path jail, file operations, the key-value store, CSP and the `ewapp://` request handler. It builds and tests on any machine.
- The `earlyweb` Tauri crate is thin glue: it registers commands, the URI scheme, the updater and the single-instance plugin, plus an `e2e` cargo feature.
- The `e2e` feature runs a self-test. The shell launches a hostile app that tries every IPC escape, and Rust judges the result and sets the process exit code. No WebDriver is needed, so it runs on all three OS webviews in CI.

**Tech Stack:** Tauri v2 (`tauri`, `tauri-build`, `tauri-plugin-updater`, `tauri-plugin-single-instance`), `@tauri-apps/cli`, `@tauri-apps/api`, Rust stable with `serde`, `serde_json`, `http`, `percent-encoding`, `regex`, plus `tempfile` (dev only). GitHub Actions with `tauri-apps/tauri-action`.

**Spec:** `PLAN.md`: §3.1, §3.7, §4.1, §4.3, §6.1, §6.3 and §7 "M1.5". The M1 plan, `docs/superpowers/plans/2026-11-06-m1-it-boots.md`, describes the code this plan builds on.

## Global Constraints

- Everything in the M1 plan's Global Constraints still holds: Node ≥ 22, pnpm ≥ 9, strict TS, ESM, the iframe gets exactly `sandbox="allow-scripts"`, `allow=""` and `referrerpolicy="no-referrer"`, never `allow-same-origin`, and apps import only `@earlyweb/sdk` and `@earlyweb/ui-kit`.
- New JS dependencies, and only these: `@tauri-apps/cli` (root, dev) and `@tauri-apps/api` (shell). New Rust dependencies, and only these: those listed in Tech Stack. Ask before adding anything else.
- **Only `packages/shell/src/platform.ts` may import `@tauri-apps/api`.** `packages/backends` receives an injected `Invoke` function and never imports Tauri.
- Tauri app identifier `org.earlyweb.desktop`, product name `EarlyWeb`, binary `earlyweb`. The version comes from the root `package.json` (`"version": "0.1.0"`), and `tauri.conf.json` reads it with `"version": "../package.json"`.
- The EarlyWeb home defaults to `~/EarlyWeb` (`EARLYWEB_HOME` overrides it). The data dir defaults to Tauri's `app_data_dir()` (`EARLYWEB_DATA` overrides it).
- The app origin is `ewapp://localhost` on Linux/macOS and `http://ewapp.localhost` on Windows. App URLs are `<origin>/<appId>/<version>/<file>`, the same layout the M1 app server uses.
- The shell origin is `tauri://localhost` on Linux/macOS and `http://tauri.localhost` on Windows. In `tauri dev` it is the `devUrl` origin.
- Updater endpoint: `https://github.com/tboskkk/earlyweb/releases/latest/download/latest.json`.
- Rust passes `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`. Commands return `Result<T, FsError>`. No `unwrap()` outside tests.
- Release bundles must never contain test fixtures (`test.earlyweb.*`) or the `e2e` feature.

**Deliberate deviations from PLAN.md (call them out in review, don't silently "fix" them):**

- All bundled apps share one `ewapp` origin, with the app id in the path. Windows maps custom schemes to a fixed `http://<scheme>.localhost` host, so `ewapp://<appId>/` can't work there. The apps are opaque-origin sandboxes either way.
- File grants stay in the trusted shell in M1.5. Rust jails every path but doesn't re-check grants: only the shell can reach Rust, so that check would guard the shell against itself. It moves to M2, with mounts. Grants persist through the Rust key-value store.
- `/mnt` (mounts), folder watch and `.trash` are M2.

## Review Focus

1. **File names that Windows or macOS can't store** (`con.txt`, `a:b.txt`, `name.`, `name `), typed on Linux. Expected: a clear `EINVAL` saying why, never a file written somewhere else, so a home folder synced between OSes stays valid. Test: Task 2, `segment_rules`.
2. **A symlink in `~/EarlyWeb/Documents` pointing outside the home** (for example to `/etc`). Expected: reading through it fails with `EPERM`, listing skips it, and nothing outside the home is ever read or written. Test: Task 2, `escaping_symlink_is_eperm`; Task 3, `list_skips_escaping_symlink`.
3. **A crash or power loss during save.** Expected: the old file stays intact (writes go to a temp file, then a rename), and the temp file never appears in listings. Test: Task 3, `write_is_atomic_and_temp_hidden`.
4. **`~/EarlyWeb` already exists with the user's files, or exists as a plain file.** Expected: existing files are untouched, and a file in that spot gives a readable boot error instead of a crash. Test: Task 2, `existing_home_is_kept` and `home_is_file_errors`.
5. **A corrupt or half-written state file** (the session or grants). Expected: boot continues with that key empty, and the bad file is logged, not fatal. Test: Task 4, `corrupt_value_reads_as_none`.

### Task 2: Virtual-path jail (`core/src/vfs.rs`, `core/src/error.rs`)

**Files:**

- Create: `src-tauri/core/src/{error.rs,vfs.rs}`, `src-tauri/core/tests/vfs.rs`

**Interfaces:**

- Produces:
  - `pub struct FsError { pub code: &'static str, pub message: String }`. It is `Serialize` with fields `code` and `message`. The codes are exactly the protocol's: `EPERM ENOENT EEXIST EINVAL EQUOTA`.
  - `impl From<std::io::Error> for FsError`: `NotFound`→`ENOENT`, `AlreadyExists`→`EEXIST`, `PermissionDenied`→`EPERM`, `StorageFull`→`EQUOTA`, anything else→`EINVAL` with the io message.
- Produces:
  - `pub struct Vfs`, built with `Vfs::new(home: PathBuf, data: PathBuf) -> Result<Vfs, FsError>`. It creates both directories if missing, canonicalizes them and stores the result. It fails with `EINVAL "<path> exists and is not a folder"` if either exists as a file.
  - `pub enum Node { Virtual(&'static [&'static str]), Real { root: PathBuf, path: PathBuf, is_root: bool } }`.
  - `impl Vfs { pub fn resolve(&self, vpath: &str) -> Result<Node, FsError> }`.
  - Mapping: `/` → `Virtual(["apps","home","system","tmp"])`, `/home` → `Virtual(["user"])`, `/home/user/**` → home, `/apps/**` → `data/apps`, `/system/**` → `data/system`, `/tmp/**` → `data/tmp`. Anything else is `ENOENT`.

- [ ] **Step 1: Write the failing tests in `core/tests/vfs.rs`** (use `tempfile::tempdir()`).
  - `normalizes_like_js`: `resolve("/home/user/./Documents//a.txt")` gives the real path `<home>/Documents/a.txt`. `resolve("/home/user/../../x")` is `EINVAL`, and so is a relative path (`"a.txt"`). These mirror `normalizePath` in `packages/backends/src/path.ts`.
  - `maps_roots`: each mapping above resolves to the expected real path. `/mnt/x` and `/etc` are `ENOENT`. `resolve("/home/user")` has `is_root == true`.
  - `segment_rules`: each of these is `EINVAL`: `/home/user/con.txt`, `/home/user/Lpt9`, `/home/user/a:b`, `/home/user/a*b`, `/home/user/a?b`, `/home/user/a"b`, `/home/user/a<b`, `/home/user/a|b`, `/home/user/a\b`, `/home/user/name.`, `/home/user/name `, a 256-byte segment, and a segment with `\u{7}`. The message names the rule. These are accepted: `/home/user/console.txt`, `/home/user/.hidden`, `/home/user/ünïcødé.txt`.
  - `escaping_symlink_is_eperm` (`#[cfg(unix)]`): `<home>/Documents/link` → `/etc`. `resolve("/home/user/Documents/link/passwd")` is `EPERM`, and so is the link itself. A symlink to `<home>/Music` resolves fine.
  - `existing_home_is_kept`: pre-create `<home>/Documents/old.txt`, call `Vfs::new`, and the file is still there with the same bytes.
  - `home_is_file_errors`: if `<home>` is a file, `Vfs::new` returns `EINVAL` and the file is unchanged.
- [ ] **Step 2: Run** `cargo test -p earlyweb-core --test vfs`. Expected: FAIL (doesn't compile).
- [ ] **Step 3: Implement `resolve`.**
  - Normalize segments with the JS rules, then validate each segment under a real root: Windows reserved base names, case-insensitive and with any extension; the characters `\ : * ? " < > |`; controls; a trailing `.` or space; more than 255 bytes.
  - Jail: canonicalize the deepest existing ancestor of the joined path and require `starts_with(canonical_root)`. If not, return `EPERM "outside the EarlyWeb folder"`. Non-existent tail segments are fine, since they're already free of `..`.
- [ ] **Step 4: Run** the tests. Expected: PASS.
- [ ] **Step 5: Commit** `feat(core): virtual path jail with portable name rules`

### Task 3: File operations and Tauri fs commands

**Files:**

- Create: `src-tauri/core/src/ops.rs`, `src-tauri/core/tests/ops.rs`, `src-tauri/src/commands.rs`
- Modify: `src-tauri/src/lib.rs`, `src-tauri/build.rs`, `src-tauri/capabilities/shell.json`, `src-tauri/core/Cargo.toml`

**Interfaces:**

- Consumes: `Vfs`, `Node` and `FsError` (Task 2).
- Produces:
  - `#[derive(Serialize)] pub struct FsStat { path: String, name: String, kind: &'static str /* "file"|"dir" */, size: u64, mtime: f64 /* ms since epoch */ }`.
  - `impl Vfs` methods: `stat(&str) -> Result<Option<FsStat>>`, `list(&str) -> Result<Vec<FsStat>>` (unsorted, because TS sorts), `read(&str) -> Result<Vec<u8>>`, `write(&str, &[u8]) -> Result<()>`, `mkdir(&str)`, `remove(&str)`, `rename(&str, &str)`.
  - Semantics and error codes match `createIdbFs` exactly (see `packages/backends/src/web/idb-fs.ts` and its tests). On top of that:
    - `Virtual` nodes stat as dirs and list their children.
    - `write`, `remove` and `rename` on a `Virtual` node, or `remove("/home/user")`, are `EINVAL`.
    - The roots `/apps`, `/system` and `/tmp` can be removed and recreated (`ensureHome` does this to `/tmp`).
- Produces: Tauri commands, each `async`, taking `State<'_, AppState>`, where `struct AppState { vfs: Result<Vfs, FsError> }` (`FsError: Clone`):
  - `fs_stat{path}` → `FsStat|null`
  - `fs_list{path}` → `FsStat[]`
  - `fs_read{path}` → raw bytes via `tauri::ipc::Response`
  - `fs_write(request: tauri::ipc::Request)`: the body is `InvokeBody::Raw` and the path is in header `x-ew-path`, percent-encoded. A JSON body is `EINVAL`.
  - `fs_mkdir{path}`, `fs_remove{path}`, `fs_rename{from,to}`.
  - Errors serialize as `{code,message}`.
  - `setup` builds the `Vfs` from the env/default dirs and never panics. If `Vfs::new` failed, every fs command returns that error. The shell's `ensureHome` then throws, and the existing boot-error text in `main.tsx` shows `EarlyWeb failed to start: <message>`. This is the user-visible half of Review Focus 4.

  - `struct E2e { token: String, canary_reads: AtomicUsize }`. `fs_read` and `fs_stat` increment `canary_reads` when the virtual path is the canary.
  - Commands: `e2e_canary() -> String` and `e2e_report{app: String}`. `e2e_report` prints one line, `EW-SELFTEST {"app":…,"fileOnDisk":bool,"canaryReads":n}`, then exits 0 only if `app == "blocked"`, the real `<home>/Documents/canary.txt` equals the token, and `canary_reads == 0`.   - `frameShell`: add an iframe for `tauri://localhost/` and one for `http://tauri.localhost/`. Reading its `contentWindow.__TAURI_INTERNALS__` returns an object → LEAK.
